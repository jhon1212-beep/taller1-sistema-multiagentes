# SP-002 · Confirmar Google Drive como tercera fuente (vs. Jira Cloud)

**Responsable (R):** Chávez · **Semana:** 5 (Sprint 1) · **Tipo:** spike de decisión
**Evidencia esperada (Product Backlog v6.0):** matriz comparativa + respuesta JSON de prueba + decisión registrada.

> Documento preparado para el repositorio con la decisión que ya está aplicada en el código
> (`fuente.tipo` solo admite `github`, `notion` y `drive`). Chávez lo revisa y, si en Notion
> quedó una versión propia, la enlaza aquí.

## 1. Pregunta

El sistema lee el avance de cada proyecto desde tres fuentes: código (GitHub), tareas
(Notion) y una tercera fuente. ¿Debe ser Google Drive (documentación del proyecto) o
Jira Cloud (gestión de incidencias)?

## 2. Matriz comparativa

| Criterio | Google Drive (API v3) | Jira Cloud (REST API v3) |
|---|---|---|
| Qué aporta al seguimiento | Documentos del proyecto: quién los editó y cuándo (evidencia de documentación, regla R4) | Incidencias y su flujo; **se superpone con Notion**, que ya cubre las tareas (I1–I3, R1–R2) |
| Uso real en los equipos del curso | Los grupos ya entregan informes y actas en carpetas compartidas | Ningún grupo del curso lo usa; habría que pedirles migrar sus tareas |
| Costo | Gratuito con un proyecto de Google Cloud y una cuenta de servicio | Plan Free gratuito hasta 10 usuarios |
| Autenticación | Cuenta de servicio (JSON), solo lectura: `drive.readonly`. El equipo comparte la carpeta con el correo de la cuenta | Correo + API token por Basic Auth, o OAuth 2.0. El token es personal de un usuario del sitio Jira de cada equipo |
| Acceso a fuentes de otros equipos | Basta con que el equipo comparta su carpeta como Lector | Cada equipo tendría que invitar a un usuario del sistema a su sitio Jira |
| Datos que necesita el motor | `name`, `modifiedTime`, `lastModifyingUser`, `mimeType` (comprobados en EN-004) | `summary`, `status`, `assignee`, `duedate`, `updated` (duplican las propiedades de Notion) |
| Esfuerzo estimado de integración | 1 adaptador (lista de archivos por carpeta) | 1 adaptador + mapeo de estados por flujo de trabajo de cada equipo |

## 3. Respuesta de prueba

Google Drive: `docs/sprint2/evidencias/EN-004_drive.json` (HTTP 200 en `files.list`,
10 archivos listados con los 5 campos que usa el motor) y la captura de cuota
`docs/sprint2/evidencias/EN-004_cuota.png`.

Jira Cloud no se probó contra un sitio real porque ningún equipo del curso tiene uno; la
comparación se hizo con la documentación oficial (fuentes al final).

## 4. Decisión

**Google Drive es la tercera fuente.** Aporta una evidencia que GitHub y Notion no
cubren (la documentación) y no exige que los equipos cambien de herramienta. Jira
duplicaría lo que ya da Notion.

Ajuste posterior (semana 12): **Drive es opcional** por proyecto. Un equipo sin carpeta
compartida se registra solo con GitHub y Notion; la fuente aparece como «No configurada»
y no se evalúa R4 (ver `docs/tecnica.md`, sección 1.4).

Si en el futuro se quisiera Jira, el cambio es acotado: un adaptador nuevo que cumpla el
puerto `FuenteEvidencia` y una migración que agregue `jira` al CHECK de `fuente.tipo`
(`docs/modelo-de-datos.md`).
