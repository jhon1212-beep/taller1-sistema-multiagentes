# HU-002: Registrar proyecto académico

## Descripción
Implementación de las rutas API en FastAPI y persistencia en PostgreSQL (Neon) para la gestión del ciclo de vida de proyectos académicos (crear, listar, editar y desactivar), incluyendo equipo de integrantes y sus 3 fuentes de evidencia (GitHub, Notion y Google Drive).

## Criterios de Aceptación
- [x] Registra el proyecto completo con integrantes, referencias de las 3 fuentes, URL pública y elemento a verificar respondiendo HTTP 201 (CP-04).
- [x] Valida que proyectos con nombre en blanco o solo espacios no se guarden, respondiendo HTTP 422 (CP-05).
- [x] Operaciones del ciclo CRUD (Crear, Listar, Editar y Desactivar) funcionando correctamente sobre PostgreSQL.
- [x] Colección OpenAPI exportada en `docs/sprint1/evidencias/HU-002_coleccion.json`.

## Cómo se probó
1. **Pruebas unitarias:** Se ejecutaron las pruebas con `python -m pytest -q` aprobando las 10 pruebas nuevas del módulo `test_proyectos.py`.
2. **Pruebas de API en Swagger UI (/docs):**
   - `POST /proyectos`: Se registró un proyecto válido obteniendo respuesta `201 Created`.
   - `POST /proyectos` (sin nombre): Se validó la restricción obteniendo `422 Unprocessable Entity`.
   - `PUT /proyectos/1`: Se editaron los campos del proyecto obteniendo `200 OK`.
   - `GET /proyectos`: Se listó el proyecto activo.
   - `PATCH /proyectos/1/desactivar`: Se desactivó el proyecto obteniendo `200 OK`.
   - `GET /proyectos`: Se confirmó que el proyecto desactivado ya no aparece en la lista (`[]`).
3. **Verificación SQL:** Se realizaron las consultas en Neon confirmando la inserción en las tablas `proyecto`, `integrante` y `fuente`.
4. **Exportación de Colección:** Se guardó la especificación OpenAPI desde `http://localhost:8000/openapi.json`.
