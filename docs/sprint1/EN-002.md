# EN-002 — Configuración y verificación de Notion API

## 1. Descripción

Se configuró la integración entre el proyecto **Taller 1 - Sistema Multiagentes** y Notion con el objetivo de permitir la consulta de información de una base de datos de tareas mediante la API de Notion.

Para realizar la prueba se creó la base **Base Demo - Taller 1**, se configuró una integración interna con permisos de lectura y se verificó el acceso mediante un script en Python.

La validación se realizó utilizando la versión de API:

`2025-09-03`

---

## 2. Criterios de aceptación

| N.° | Criterio | Resultado | Evidencia |
|---|---|---|---|
| 1 | `NOTION_TOKEN` guardado como variable de entorno y protegido del repositorio. | Cumple | `.env` ignorado mediante `.gitignore` y `.env.example` utilizado como plantilla. |
| 2 | La consulta a la base demo responde HTTP 200. | Cumple | `EN-002_consola.png` y `EN-002_notion.json`. Se obtuvieron tres respuestas HTTP 200. |
| 3 | Se documentan las propiedades `Tarea`, `Responsable`, `Estado` y `Fecha límite`. | Cumple | Validación automática mediante `verificar_notion.py` y evidencia `EN-002_notion.json`. |

---

## 3. Configuración de la base demo

Se creó en Notion la base de datos **Base Demo - Taller 1** con cuatro tareas de prueba.

La integración **Taller 1 - Sistema Multiagentes** fue conectada a esta base con permisos de lectura, sin permisos para actualizar o insertar contenido.

Las propiedades utilizadas fueron:

| Propiedad | Tipo en Notion API |
|---|---|
| Tarea | `title` |
| Responsable | `people` |
| Estado | `status` |
| Fecha límite | `date` |

El script verificó automáticamente que las cuatro propiedades estuvieran presentes y correspondieran con los tipos esperados.

---

## 4. Verificación mediante la API

Se implementó el script:

`backend/scripts/verificar_notion.py`

El script carga `NOTION_TOKEN` y `NOTION_DATABASE_ID` desde el archivo `.env`, evitando almacenar las credenciales directamente en el código.

Durante la ejecución se obtuvieron los siguientes resultados:

| Operación | Resultado |
|---|---|
| Consultar database | HTTP 200 |
| Consultar data source | HTTP 200 |
| Consultar registros del data source | HTTP 200 |
| Propiedad `Tarea` | ok |
| Propiedad `Responsable` | ok |
| Propiedad `Estado` | ok |
| Propiedad `Fecha límite` | ok |
| Filas leídas | 4 |

La evidencia técnica se almacenó en:

`docs/sprint1/evidencias/EN-002_notion.json`

El archivo JSON guarda únicamente los códigos HTTP, nombres y tipos de propiedades y cantidad de filas leídas. No almacena nombres ni correos de las personas registradas en Notion.

---

## 5. Hallazgo técnico

Durante el desarrollo de EN-002 se identificó un cambio relevante en la API de Notion.

El Product Backlog consideraba la consulta:

`/v1/databases/{id}/query`

Sin embargo, con la versión de API `2025-09-03`, la base contiene uno o más `data_sources`. Por este motivo, primero se obtiene el `data_source` asociado a la base y posteriormente las tareas se consultan mediante:

`/v1/data_sources/{id}/query`

Este cambio deberá ser corregido durante el refinamiento de la **semana 6**, para que el Product Backlog refleje la implementación utilizada actualmente.
