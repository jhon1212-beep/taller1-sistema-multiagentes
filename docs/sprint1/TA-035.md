# TA-035 · Integración continua

Implementación: [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml).

Se ejecuta con cada push, cada pull request y manualmente desde Actions. Dos trabajos independientes verifican:

| Trabajo | Entorno | Verificación |
|---|---|---|
| Backend - pytest | Ubuntu, Python 3.12 | Instala `backend/requirements-agentes.txt` y ejecuta todas las pruebas de `tests/`; guarda el reporte JUnit durante 14 días, incluso si hay pruebas fallidas. |
| Frontend - build | Ubuntu, Node.js 22 | Instala con `npm ci` usando el lockfile y compila con `npm run build`. |

Un error de instalación, prueba o compilación hace fallar el trabajo. No se usan secretos, bases de datos ni APIs externas para las pruebas. El workflow solo tiene permiso de lectura del repositorio y limita cada trabajo a diez minutos.

## Reproducir localmente

Desde la raíz, con el entorno virtual activo y las versiones indicadas:

```bash
python -m pip install -r backend/requirements-agentes.txt
python -m pytest -q --junitxml=test-results/pytest.xml
npm ci --prefix frontend
npm run build --prefix frontend
```

## Evidencia de ejecución remota

Validación local de esta corrección (2026-10-05, Lima): **9 pruebas aprobadas** y **compilación de Vite correcta**, con Windows, Python 3.11.9 y Node.js 24.18.0. Se instaló el archivo de requisitos completo y se usó `npm ci`. También se comprobó la estructura YAML y los eventos del workflow. Esta validación local no sustituye la ejecución en Ubuntu con Python 3.12 y Node.js 22 configurada en Actions.

Después de subir los cambios, abrir **Actions → TA-035 - Integracion continua** y registrar el enlace a la ejecución, commit y resultado de ambos trabajos. Descargar `resultados-pytest` para consultar el reporte. La opción manual aparece una vez que el workflow está en la rama predeterminada.

La creación del archivo no demuestra una ejecución en GitHub. Esta corrección no incluye una ejecución remota ni configura reglas de protección de ramas. Para exigir estos controles antes de fusionar, un administrador debe seleccionarlos como comprobaciones obligatorias en las reglas de la rama.

El alcance funcional de cada prueba y sus pendientes se detalla en [TA-003](TA-003.md); CI no declara aprobadas funciones todavía sin implementar.
