# TA-006 — Adaptador y Agente GitHub

## 1. Descripción

Se implementó `FuenteEvidenciaGitHub`, la implementación real del puerto `FuenteEvidencia` (AR-01) para GitHub, y `agente_github`, el nodo de LangGraph que la orquesta y maneja sus fallos. Reutiliza el cliente de solo lectura de EN-001 (`cliente.py`), al que se le agregó `commits_detallados()` para obtener el SHA completo de cada commit (el método original `commits()` lo trunca a 7 caracteres para lectura humana).

Código:
- `backend/app/modulos/evidencias/adaptadores/github/cliente.py` (EN-001, reubicado)
- `backend/app/modulos/evidencias/adaptadores/github/adaptador.py` (TA-006)
- `backend/app/modulos/evidencias/agentes/agente_github.py` (TA-006)

Pruebas: `tests/test_agente_github.py`

## 2. Criterios de aceptación

| N.° | Criterio | Resultado | Evidencia |
|---|---|---|---|
| 1 | Recupera hasta 20 commits con autor, fecha, mensaje y SHA. | Cumple | `TA-006_salida_real.json` |
| 2 | 5 de 5 commits coinciden con la API. | _Pendiente de verificar contra el repositorio real_ | `TA-006_comparacion.png` |
| 3 | Las pruebas pytest del agente pasan. | Cumple | `TA-006_pytest.png` |

`docs/sprint1/evidencias/TA-006_salida_ejemplo.json` muestra el formato de salida con datos simulados (misma técnica que las pruebas unitarias, sin red ni token). El archivo `TA-006_salida_real.json` de la tabla es la salida real contra el repositorio del equipo, que generas en el paso 3 de abajo con tu propio `GITHUB_TOKEN`.

## 3. Cómo se probó

Las pruebas unitarias simulan el cliente de GitHub (no dependen de red ni de un `GITHUB_TOKEN`, pasan igual en cualquier máquina o en CI). Verifican la normalización, el límite de 20 commits y el manejo controlado de errores de la API.

La verificación contra la API real (criterio 2) es manual:

```bash
cd backend
python -m app.modulos.evidencias.agentes.agente_github > ../docs/sprint1/evidencias/TA-006_salida_real.json
```

El repositorio por defecto es `jhon1212-beep/taller1-sistema-multiagentes`; se puede apuntar a otro con la variable `TA006_REPO`. Luego se comparan 5 commits de esa salida contra la pestaña *Commits* del repositorio en GitHub.
