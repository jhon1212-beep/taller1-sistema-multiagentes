# HU-004: Vista de tareas (Notion)

Estimación del backlog: 1 SP · 4 h.  
Fecha de implementación: 13/10/2026.  
Estado: implementado y probado; pendiente de revisión.

## Descripción

El docente puede ver, dentro del detalle de un proyecto, las tareas de su
base de Notion con responsable, estado y fecha límite. Antes de esta HU la
pestaña Notion mostraba solo datos de demostración del frontend; el adaptador
de Notion (TA-007) existía, pero ninguna ruta lo exponía.

## Criterios de aceptación

- [x] `GET /proyectos/{id}/tareas` devuelve las tareas de la base de Notion
      registrada en el proyecto, con responsable, estado y fecha límite.
- [x] Cada tarea sin responsable llega con `responsable = null` y la vista
      muestra "Sin responsable".
- [x] Si Notion rechaza las credenciales o falla, la respuesta es
      `estado = "fallo"` con un mensaje legible y **cero tareas**: nunca se
      inventan datos (misma regla que TA-007 y TA-015).
- [x] Un docente solo consulta las tareas de sus propios proyectos (404 si el
      proyecto no es suyo).
- [x] El frontend consume el endpoint cuando se define `VITE_API_URL`; sin esa
      variable (Netlify, prototipo) conserva los datos de demostración.

## Cómo se realizó

1. **Revisión de contexto:** `rutas.py` y `servicio.py` de `proyectos`
   (HU-002), el adaptador y el agente de Notion (TA-007), el dataset de
   TA-017 y `Detalle.jsx`.
2. **`evidencias/tareas.py`:** `consultar_tareas(fuente, referencia,
   proyecto_id, limite)` orquesta el puerto `FuenteEvidencia`, normaliza a
   `Tarea` y convierte `NotionAuthError` / `NotionError` en un
   `ConsultaTareas(estado="fallo")`. El detalle técnico del error no se
   expone al cliente.
3. **`evidencias/rutas.py`:** ruta `GET /proyectos/{id}/tareas?limite=` (1 a
   200, 100 por defecto). Reutiliza `docente_actual` y `obtener_servicio` de
   HU-002 para validar la pertenencia, y toma la referencia de Notion del
   proyecto (`fuentes.notion`). La fuente se inyecta con
   `obtener_fuente_tareas`, así las pruebas no usan red.
4. **`main.py`:** registra el router y agrega CORS configurable con
   `CORS_ORIGINS` (por defecto `localhost:5173` y `127.0.0.1:5173`).
5. **Frontend:** `api.js` agrega `API_ACTIVA` y `obtenerTareas`;
   `Detalle.jsx` agrega `TareasNotionApi` con estados de carga, error de
   conexión, fallo de Notion y tabla de tareas con resumen.
6. **Pruebas:** `tests/test_tareas_notion.py` (10 casos) usa el repositorio en
   memoria y el dataset de TA-017 como fuente de Notion.

## Respuesta de ejemplo

```json
{
  "proyecto_id": 1, "fuente": "notion", "estado": "ok", "error": null,
  "total": 20,
  "resumen": {"listo": 8, "en_curso": 6, "sin_empezar": 6, "sin_responsable": 1},
  "tareas": [
    {"id": "tarea-p1-01", "tarea": "Inicio de sesión docente · 1",
     "responsable": "Ana Torres", "estado": "Listo",
     "fecha_limite": "2026-10-05", "editada": "2026-10-01T15:00:00Z"}
  ]
}
```

## Cómo se probó

```powershell
python -m pytest tests/test_tareas_notion.py -v
python -m pytest -q
```

- `test_tareas_notion.py`: 10 passed (20 tareas con sus campos, resumen por
  estado, tarea sin responsable, límite y su rango, base de Notion del
  proyecto, credenciales rechazadas, error de red, 404 y aislamiento por
  docente).
- Suite completa: 102 passed y 1 failed. El fallo es
  `test_seguridad_secretos`, que necesita un repositorio Git y la carpeta de
  trabajo local no lo es; en un checkout con Git pasa (2 passed).
- Verificación manual con el dataset de TA-017: la pestaña Notion mostró 20
  tareas con el resumen (8 / 6 / 6 / 1).
- **Verificación contra la base real de Notion (13/10/2026):** con el
  `NOTION_TOKEN` de la integración "Taller 1 - Sistema Multiagentes" (en
  variable de entorno, sin guardarlo en archivos) la API devolvió
  `estado: "ok"`, 20 tareas (0 terminadas, 1 en curso, 19 sin empezar, 0 sin
  responsable) y la vista las mostró con responsable, estado y fecha límite.
  Con un token inválido a propósito devolvió `estado: "fallo"`, cero tareas y
  la interfaz mostró "Integración fallida: Notion rechazó las credenciales".
- Durante esa verificación se corrigió un detalle de interfaz: el mensaje de
  fallo repetía "Integración fallida" dos veces.

## Limitaciones

- El docente sigue siendo el temporal `docente_actual() = 1` hasta integrar
  la autenticación (AR-04 / HU-001).
- Las pruebas automáticas no usan la red; la verificación contra la base real
  es manual y requiere `NOTION_TOKEN` en el entorno. Conviene rotar el token
  compartido por chat.
- La lista del frontend usa proyectos de demostración; HU-002 en el frontend
  aún no está conectado a la API.
- No hay paginación en la interfaz: el límite máximo del endpoint es 200.
