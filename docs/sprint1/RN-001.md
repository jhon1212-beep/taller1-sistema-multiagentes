# RN-001 · Seguridad de secretos

## Alcance y corrección

RN-001 establece la protección de credenciales del proyecto. La revisión del 06/10/2026 encontró que la documentación anterior afirmaba excluir `service-account-*.json`, pero esa regla faltaba; también faltaban variables requeridas en `.env.example`. Esta corrección agrega las reglas y completa la plantilla.

Estimación registrada anteriormente: 0.5 SP / 2 horas. Las horas reales y la asignación de responsable/verificador deben confirmarse con el equipo: la observación recibida menciona a Castro y el documento anterior a Reyes/Mondragón.

## Reglas obligatorias

| Regla | Aplicación y comprobación |
|---|---|
| No guardar secretos en código ni documentación | Tokens, claves y cadenas de conexión reales se completan únicamente en el entorno local o en el almacén de secretos del servicio que los utilice. |
| Excluir archivos de credenciales | `.gitignore` excluye `.env`, `.env.*`, `service-account-*.json`, `client_secret_*.json`, `credentials.json`, `token.json`, `*.pem` y `*.key`, también en subcarpetas. |
| Mantener una plantilla pública | La excepción `!.env.example` permite versionarla. Sus variables sensibles se dejan vacías. No copiar valores del entorno local a esta plantilla. |
| No revelar secretos en evidencias | Omitir valores de tokens, cabeceras Authorization, contraseñas y contenido de archivos de credenciales en capturas, logs e informes. |
| Usar permisos mínimos | Las integraciones de lectura deben usar credenciales limitadas a los recursos necesarios. El workflow de TA-035 tiene `contents: read` y sus pruebas actuales no requieren secretos. |
| Revisar antes de publicar | Revisar el diff y ejecutar un detector de secretos sobre archivos e historial. `.gitignore` no elimina archivos ya versionados ni detecta credenciales incrustadas en otros archivos. |
| Responder a una exposición | Revocar o rotar la credencial comprometida, actualizar sus consumidores y coordinar la limpieza del historial. Borrar el archivo del último commit no invalida el secreto expuesto. |

## Variables requeridas

[`.env.example`](../../.env.example) incluye estos nombres, con valores vacíos:

```dotenv
GITHUB_TOKEN=
NOTION_TOKEN=
GOOGLE_SERVICE_ACCOUNT_JSON=
GEMINI_API_KEY=
LANGSMITH_API_KEY=
DATABASE_URL=
```

Se conserva la configuración adicional de GitHub y OAuth de Drive. `GOOGLE_SERVICE_ACCOUNT_JSON` representa la ruta local del archivo de credenciales cuando se utilice cuenta de servicio; no implica que ese método de autenticación ya esté implementado.

## Verificación reproducible

Desde la raíz del repositorio:

```bash
git check-ignore -v .env .env.local service-account-drive.json config/service-account-demo.json client_secret_demo.json credentials.json token.json private.pem private.key
python -m pytest -q tests/test_seguridad_secretos.py
```

Las pruebas comprueban que los archivos sensibles quedan excluidos, que `.env.example` puede versionarse y que las variables sensibles están documentadas sin valores. Se ejecutan también en TA-035 al descubrir la carpeta `tests/`. No sustituyen un escaneo de secretos.

Si Gitleaks está instalado, revisar el historial completo y los archivos que se van a publicar. Usar salida redactada y una carpeta local ignorada:

```bash
gitleaks git --redact --log-opts="--all" --report-path test-results/RN-001_historial.json
```

Crear `test-results/` antes del comando si no existe. Comprobar el código de salida: cero indica que no se detectaron secretos; un error de herramienta no equivale a un resultado limpio. Realizar la prueba positiva con un patrón sintético documentado por la versión instalada, en un directorio temporal fuera del repositorio, y confirmar que produce una detección sin publicar el patrón.
